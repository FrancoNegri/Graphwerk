### F-009 — inconsistency — open
**Location:** `graphwerk/rationale/miner.py::RationaleStore._misplaced_session_warning`
**Evidence:** This ADR-009 feature detects "the agent session ran in the
base tree, not the staging worktree" by comparing `find_latest_transcript`
results between `self.base_root` and `self.staged_root`. Since ticket 158
(this session), `bootstrap.build_app()` always constructs `RationaleStore`
with `staged_root=repo, base_root=repo` — the same directory — so the two
lookups are now always identical and the warning can never fire: dead
code. Worse, its message text still says `"or check whether --base and
--staged are swapped"` — exactly the two flags ticket 158 deleted from
`graphwerk serve`. `tests/rationale/test_miner.py` (lines ~352-407) still
unit-tests this path by deliberately constructing `RationaleStore` with
distinct `staged_root`/`base_root`, which is no longer a real production
configuration — the unit test passes, but nothing exercises it through
real wiring anymore. Not covered by ticket 161 (that ticket's scope is
`session.py`/`cycle.py`/`check.py`'s directory naming, not `rationale/`) —
ADR 058 item 5 asserted rationale mining was "unaffected," which missed
this one feature that inherently depended on two distinct directories.
**Ticket:** docs/tickets/164-drop-dead-misplaced-session-warning.md
